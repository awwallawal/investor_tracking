## Story

**As an** OYSIPA Staff Member,
**I want** to update the lifecycle stage of an investment project,
**so that** its status accurately reflects its current position in the official investment pipeline.

## Acceptance Criteria

1.  The "Project Detail" page clearly displays the project's current lifecycle stage.
2.  An "Update Stage" button or dropdown allows the user to select a new stage from a predefined list (matching the OYSIPA framework).
3.  Changing the stage updates the project's record in the database.
4.  A system-generated entry is automatically added to the interaction log, noting the stage change, the date, and the user who made the change.

## Dev Notes

- **Data Models**: 
    - **Model: InvestmentProject** [Source: architecture/4-data-models.md]
        - Key Attributes: `lifecycleStage`: `ObjectId` - A reference to the `_id` of the current `LifecycleStage`. Required.
    - **Model: LifecycleStage** [Source: architecture/4-data-models.md]
        - Purpose: To define the distinct, ordered stages of the investment pipeline.
        - Key Attributes: `_id`, `name`, `order`, `description`.
    - **Model: InteractionLog** [Source: architecture/4-data-models.md]
        - Purpose: To record a single, timestamped support activity or event.
        - Key Attributes: `project`, `loggedBy`, `description`, `category`, `createdAt`.

- **API Specifications**: 
    - `PUT /projects/{id}`: Update a project. [Source: architecture/5-api-specification.md]
        - Request Body: `InvestmentProjectRequest` (includes `lifecycleStage`).
    - `POST /projects/{projectId}/interactions`: Create a new interaction log. [Source: architecture/5-api-specification.md]
        - Request Body: `InteractionLogRequest` (description, category).

- **File Locations**:

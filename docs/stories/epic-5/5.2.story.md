## Story

**As a** Staff Member,
**I want** to send periodic emails to investors,
**so that** I can maintain engagement and provide updates.

## Acceptance Criteria

1.  An admin interface exists to create and manage a library of email templates.
2.  A feature exists on the investor page to select a template and send it to the investor's primary contact.
3.  A record of the email being sent is automatically added to the investor's interaction log.

## Tasks / Subtasks

- [ ] **Backend**
    - [ ] Create a new `EmailTemplate` model with `name` and `body` fields.
    - [ ] Create a full set of CRUD API endpoints for `EmailTemplate` (`GET`, `POST`, `PUT`, `DELETE`), restricted to 'Portal Administrator' users.
    - [ ] Create a new endpoint `POST /api/investors/:investorId/send-email` for Staff Members.
        - [ ] This endpoint should take an `emailTemplateId` in the request body.
        - [ ] It should find the primary contact for the investor.
        - [ ] It should simulate sending the email (e.g., log to the console). **Note: No real email sending service is required for this story.**
        - [ ] It must create a new `InteractionLog` entry for the project, noting that an email was sent.
- [ ] **Frontend**
    - [ ] Create a new `EmailTemplateManager.jsx` component within the `AdminPage.jsx` for managing email templates.
        - [ ] This component will have a UI for listing, creating, editing, and deleting templates.
    - [ ] On the `InvestorProfilePage.jsx`, add a "Send Email" button.
    - [ ] Clicking the "Send Email" button should open a dialog (`SendEmailDialog.jsx`).
    - [ ] The `SendEmailDialog.jsx` should:
        - [ ] Fetch and display a list of available email templates.
        - [ ] Allow the user to select a template and see a preview.
        - [ ] Have a "Send" button that calls the `POST /api/investors/:investorId/send-email` endpoint.
- [ ] **Testing**
    - [ ] Write backend tests for the `EmailTemplate` CRUD endpoints.
    - [ ] Write a backend test for the `send-email` endpoint to verify it creates an interaction log.
    - [ ] Write frontend tests for the `EmailTemplateManager.jsx` component.
    - [ ] Write frontend tests for the `SendEmailDialog.jsx` component.

## Dev Notes

- **Data Models**:
    - A new `EmailTemplate` model is required (`name: String`, `body: String`).
    - The `Contact` model's `isPrimary` field will be used to identify the recipient. [Source: `docs/architecture/4-data-models.md`]
    - A new `InteractionLog` will be created automatically. [Source: `docs/architecture/4-data-models.md`]

- **Email Simulation**: For the scope of this story, the actual sending of an email is not required. The backend should simply log the content of the would-be email to the console to prove the mechanism works.

- **API Design**:
    - `GET /api/email-templates`: Get all templates.
    - `POST /api/email-templates`: Admin only.
    - `PUT /api/email-templates/:id`: Admin only.
    - `DELETE /api/email-templates/:id`: Admin only.
    - `POST /api/investors/:investorId/send-email`: Staff only.

- **File Locations**:
    - **Backend Model**: `oysipa-backend/src/models/EmailTemplate.js`.
    - **Backend Routes**: `oysipa-backend/src/api/emailTemplates.js` and `oysipa-backend/src/api/investors.js`.
    - **Backend Controllers**: `oysipa-backend/src/controllers/emailTemplateController.js` and `oysipa-backend/src/controllers/investorController.js`.
    - **Frontend Components**: `oysipa-frontend/src/components/EmailTemplateManager.jsx`, `oysipa-frontend/src/components/SendEmailDialog.jsx`.

- **Testing**:
    - Backend tests for the send-email endpoint should verify that the interaction log is created correctly.
    - Frontend tests for the dialog should mock the API calls and confirm the dialog closes on success.

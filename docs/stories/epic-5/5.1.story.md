## Story

**As a** Portal Administrator,
**I want** to create, view, edit, and re-order the system's lifecycle statuses,
**so that** I can customize the investment pipeline to our agency's evolving process.

## Acceptance Criteria

1.  A new "Admin Settings" area is available to Portal Administrators.
2.  Within this area, a "Lifecycle Statuses" page provides full CRUD functionality for the statuses.
3.  The interface allows changing the order of the statuses.
4.  The updated statuses and their order are immediately reflected in the dropdown on the "Project Detail" page.

## Tasks / Subtasks

- [x] **Backend**

    - [x] The `POST`, `PUT`, and `DELETE` endpoints must be restricted to users with the 'Portal Administrator' role.

## Dev Notes

- **Data Model**: `LifecycleStatus` (`name`, `order`, `description`). The `order` attribute is critical for this story. [Source: `docs/architecture/4-data-models.md`]

- **API Design**:
    - `GET /api/lifecycle-statuses`: Publicly accessible to get all statuses for forms.
    - `POST /api/lifecycle-statuses`: Admin only.
    - `PUT /api/lifecycle-statuses/:id`: Admin only.
    - `DELETE /api/lifecycle-statuses/:id`: Admin only.
    - A new middleware should be created to check for the 'Portal Administrator' role.

- **Frontend UI**:
    - For re-ordering, a library like `react-beautiful-dnd` could be used, or a simpler implementation with up/down arrows for each item in the list.
    - The UI should provide clear feedback to the user when statuses are created, updated, or deleted.

- **File Locations**:
    - **Backend Routes**: `oysipa-backend/src/api/lifecycleStatuses.js`.
    - **Backend Controller**: `oysipa-backend/src/controllers/lifecycleStatusController.js`.
    - **Frontend Page**: `oysipa-frontend/src/pages/AdminPage.jsx`.
    - **Frontend Component**: `oysipa-frontend/src/components/LifecycleStatusManager.jsx`.

- **Testing**:
    - Backend tests should cover success cases, failure cases (e.g., validation errors), and authorization checks.
    - Frontend tests should mock the API calls and verify that the component state and UI update correctly based on user actions.

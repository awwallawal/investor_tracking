## Story

**As a** Portal Administrator,
**I want** to create, view, edit, and re-order the system's lifecycle stages,
**so that** I can customize the investment pipeline to our agency's evolving process.

## Acceptance Criteria

1.  A new "Admin Settings" area is available to Portal Administrators.
2.  Within this area, a "Lifecycle Stages" page provides full CRUD functionality for the stages.
3.  The interface allows changing the order of the stages.
4.  The updated stages and their order are immediately reflected in the dropdown on the "Project Detail" page.

## Tasks / Subtasks

- [ ] **Backend**
    - [ ] Create a full set of CRUD API endpoints for `LifecycleStage` (`GET`, `POST`, `PUT`, `DELETE`).
    - [ ] The `POST`, `PUT`, and `DELETE` endpoints must be restricted to users with the 'Portal Administrator' role.
    - [ ] The `PUT` endpoint should handle updates to `name`, `description`, and `order`.
- [ ] **Frontend**
    - [ ] Create a new page component `AdminPage.jsx` that serves as a container for all admin settings.
    - [ ] Create a new component `LifecycleStageManager.jsx` to handle the display and management of lifecycle stages.
    - [ ] In `LifecycleStageManager.jsx`, implement a UI to:
        - [ ] Display the list of current lifecycle stages.
        - [ ] Allow for the creation of a new stage (name, description).
        - [ ] Allow for the editing of an existing stage.
        - [ ] Allow for the deletion of a stage.
        - [ ] Implement a mechanism (e.g., drag-and-drop, or up/down arrows) to change the `order` of the stages.
    - [ ] Add a link to the `/admin` page in the main navigation, visible only to Portal Administrators.
    - [ ] Ensure the `ProjectForm` component (used on the Project Detail page) fetches the latest lifecycle stages so the dropdown is always up-to-date.
- [ ] **Testing**
    - [ ] Write API integration tests for all CRUD endpoints for lifecycle stages, including role-based access control.
    - [ ] Write component tests for `LifecycleStageManager.jsx` to verify creating, editing, deleting, and re-ordering functionality.

## Dev Notes

- **Data Model**: `LifecycleStage` (`name`, `order`, `description`). The `order` attribute is critical for this story. [Source: `docs/architecture/4-data-models.md`]

- **API Design**:
    - `GET /api/lifecycle-stages`: Publicly accessible to get all stages for forms.
    - `POST /api/lifecycle-stages`: Admin only.
    - `PUT /api/lifecycle-stages/:id`: Admin only.
    - `DELETE /api/lifecycle-stages/:id`: Admin only.
    - A new middleware should be created to check for the 'Portal Administrator' role.

- **Frontend UI**:
    - For re-ordering, a library like `react-beautiful-dnd` could be used, or a simpler implementation with up/down arrows for each item in the list.
    - The UI should provide clear feedback to the user when stages are created, updated, or deleted.

- **File Locations**:
    - **Backend Routes**: `oysipa-backend/src/api/lifecycleStages.js`.
    - **Backend Controller**: `oysipa-backend/src/controllers/lifecycleStageController.js`.
    - **Frontend Page**: `oysipa-frontend/src/pages/AdminPage.jsx`.
    - **Frontend Component**: `oysipa-frontend/src/components/LifecycleStageManager.jsx`.

- **Testing**:
    - Backend tests should cover success cases, failure cases (e.g., validation errors), and authorization checks.
    - Frontend tests should mock the API calls and verify that the component state and UI update correctly based on user actions.

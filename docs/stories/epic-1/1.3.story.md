# Story 1.3: User Authentication

## Status

Done

## Story

**As an** OYSIPA User,
**I want** to log in to the application securely with my email and password,
**so that** I can access the system's features.

## Acceptance Criteria

1.  A login page exists with fields for email and password.
2.  Users are successfully authenticated against the credentials stored in the database.
3.  A secure session token (JWT) is generated upon successful login.
4.  Users are shown a clear error message if authentication fails.
5.  A "Logout" button exists and successfully terminates the user's session (client-side).

## Tasks / Subtasks

- [x] **Backend (oysipa-backend)**
    - [x] Create a new route file for authentication (`src/api/auth.js`).
    - [x] Implement a `POST /api/auth/login` endpoint.
    - [x] The endpoint should validate incoming `email` and `password`.
    - [x] It must find the user by email in the database.
    - [x] It must use `bcryptjs` to compare the provided password with the stored hash.
    - [x] If authentication is successful, generate and return a JSON Web Token (JWT).
    - [x] If authentication fails, return an appropriate error response (e.g., 401 Unauthorized).
    - [x] Add a `JWT_SECRET` to the `.env` configuration file.

- [x] **Frontend (oysipa-frontend)**
    - [x] Create a new `LoginPage` component (`src/pages/Login.jsx`).
    - [x] Create a form with controlled inputs for email and password.
    - [x] On form submission, call the `POST /api/auth/login` endpoint.
    - [x] Upon successful login, store the received JWT securely (e.g., in local storage or a state management store).
    - [x] Redirect the user to a placeholder dashboard page after login.
    - [x] Display a user-friendly error message if the login API call fails.
    - [x] Create a `LogoutButton` component that clears the stored JWT and redirects the user to the login page.

## Dev Notes

- **Authentication:** Use JSON Web Tokens (JWT) for managing user sessions. The `jsonwebtoken` library is already installed.
- **Password Comparison:** **Never** compare plain-text passwords. Always use `bcrypt.compare()` to check if a provided password matches the stored hash.
- **Error Handling:** The backend should return clear, non-specific error messages for failed logins (e.g., "Invalid credentials") to avoid revealing whether a username exists or not.
- **Frontend State:** The user's authentication status and token should be managed globally in the frontend, for example, with a Zustand store, so the application knows which user is logged in.

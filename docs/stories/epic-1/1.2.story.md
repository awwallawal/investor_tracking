# Story 1.2: User Model & Database Setup

## Status

Done

## Story

**As a** System,
**I want** the database schema for the User model to be defined and created,
**so that** user information can be securely persisted for authentication and authorization.

## Acceptance Criteria

1.  A connection to the database (MongoDB) is successfully configured and established.
2.  A `User` model and schema are created with fields for: `name` (String), `email` (String, unique), `password` (String, hashed), and `role` (String, enum: `['Director-General', 'Portal-Admin', 'Staff']`).
3.  A script or seeding process is created to initialize the database with the first Director-General user account upon application startup if no users exist.

## Tasks / Subtasks

- [x] **Backend (oysipa-backend)**
    - [x] Create a database configuration file (`src/config/database.js`) that connects to the MongoDB instance using Mongoose.
    - [x] Create a Mongoose schema and model for the `User` in `src/models/User.js`.
    - [x] Implement the seeding logic within the main application entry point (`src/index.js`) to create the initial admin user.
    - [x] Ensure the password for the initial user is properly hashed using `bcryptjs`.
    - [x] Update the main application entry point to establish the database connection on startup.

## Dev Notes

- **Database:** The project uses MongoDB as the database. All database interactions should be handled via the `mongoose` library. [Source: architecture/3-tech-stack.md]
- **Security:** Passwords must **never** be stored in plain text. Use the `bcryptjs` library to hash all passwords before they are saved to the database.
- **Configuration:** Database connection strings and other sensitive information should be managed via environment variables (`.env` file), not hardcoded.

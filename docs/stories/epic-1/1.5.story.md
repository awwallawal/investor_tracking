# Story 1.5: User Management Interface

## Status

Complete

## Story

**As a** Portal Administrator,
**I want** to invite new users and revoke access for existing users,
**so that** I can manage the system's user base in accordance with staff changes.

## Acceptance Criteria

1.  A "User Management" page is available only to `Portal Administrators` and `Director-Generals`.
2.  The page displays a list of all current users, their roles, and their status (e.g., Active/Invited/Revoked).
3.  An "Invite User" feature allows an admin to send a registration link to a new user's email address.
4.  A "Revoke Access" feature allows an admin to deactivate a user's account, preventing them from logging in.

## Tasks / Subtasks

- [x] **Backend (oysipa-backend)**
    - [x] Create a new route file for user management (`src/api/users.js`).
    - [x] Implement a `GET /api/users` endpoint to fetch a list of all users. This endpoint must be protected and accessible only by `Director-General` and `Portal-Admin` roles.
    - [x] Implement a `POST /api/users/invite` endpoint to handle user invitations. This endpoint must be protected and accessible only by `Director-General` and `Portal-Admin` roles.
    - [x] Implement a `PUT /api/users/:id/revoke` endpoint to deactivate a user's account. This endpoint must be protected and accessible only by `Director-General` and `Portal-Admin` roles.
    - [x] Consider adding a `status` field (e.g., `active`, `invited`, `revoked`) to the `User` model.

- [x] **Frontend (oysipa-frontend)**
    - [x] Create a new `UserManagementPage` component (`src/pages/UserManagementPage.jsx`).
    - [x] Implement a table to display user data (name, email, role, status).
    - [x] Implement an "Invite User" form that sends a request to the `POST /api/users/invite` endpoint.
    - [x] Implement a "Revoke Access" button for each user in the table that sends a request to the `PUT /api/users/:id/revoke` endpoint.
    - [x] Add a navigation link to the `Sidebar` for "User Management" that is only visible to `Director-General` and `Portal-Admin` roles.
    - [x] Protect the `UserManagementPage` route using the `ProtectedRoute` and role-based authorization.

## Dev Notes

- **Authorization:** Leverage the existing `auth` and `authorize` middleware for backend route protection.
- **User Status:** The `User` model will need to be updated to include a `status` field to manage active, invited, and revoked users. This will be a soft-delete mechanism.
- **Frontend UI:** Use a data table component (e.g., from Material-UI if available) for displaying the user list.
- **Invitation Mechanism:** For the MVP, the "registration link" can be a simple message to the admin to manually create the user with a temporary password, or a more sophisticated email-based invitation can be considered in a future story.

## Testing Guidance

- **Unit Tests:**
    - Backend: Test user management API endpoints (GET, POST, PUT) for correct functionality and error handling.
    - Frontend: Test `UserManagementPage` component for correct rendering of user list, invite form, and revoke buttons.
- **Integration Tests:**
    - Verify that a `Director-General` or `Portal-Admin` can successfully invite a new user and that the user appears in the list with an 'invited' status.
    - Verify that a `Director-General` or `Portal-Admin` can successfully revoke access for an existing user and that the user's status changes to 'revoked'.
    - Verify that a `Staff` user cannot access the user management API endpoints (expect 403 Forbidden).
- **End-to-End (E2E) Tests:**
    - Log in as a `Director-General` or `Portal-Admin`:
        - Navigate to the "User Management" page via the sidebar link.
        - Verify the page loads correctly and displays a list of users.
        - Use the "Invite User" feature to invite a new user. Verify the new user appears in the list.
        - Use the "Revoke Access" feature on an existing user. Verify the user's status changes.
    - Log in as a `Staff` user:
        - Verify that the "User Management" link is not visible in the sidebar.
        - Attempt to navigate directly to the "User Management" page URL; verify redirection to login or an access denied message.

## Story

**As a** OYSIPA Staff Member,
**I want** to see a personalized dashboard of all projects assigned to me when I log in,
**so that** I can get an immediate overview of my workload and priorities.

## Acceptance Criteria

1.  The default landing page after a Staff member logs in is their personal dashboard.
2.  The dashboard displays a list or a series of cards representing all investment projects currently assigned to that user.
3.  Each item in the list shows key summary information (e.g., Investor Name, Project Title, Current Lifecycle Stage).
4.  Each item is a direct link to that project's "Project Detail" page.

## Tasks / Subtasks

- [x] **Backend**
    - [x] Create a new API endpoint `GET /api/staff/dashboard` to fetch projects assigned to the logged-in staff member.
        - [x] The endpoint should use the `auth` middleware to get the user's ID.
        - [x] The controller should find all `InvestmentProject` documents where `assignedTo` matches the user's ID.
        - [x] The controller should populate the `investor` field to include the investor's name.
- [x] **Frontend**
    - [x] Modify the `Dashboard.jsx` page to be the default landing page for staff members.
    - [x] On the `Dashboard.jsx` page, fetch data from the new `GET /api/staff/dashboard` endpoint.
    - [x] Create a new component, `ProjectSummaryCard.jsx`, to display the summary information for a single project.
        - [x] The card should display the Investor Name, Project Title, and Current Lifecycle Stage.
        - [x] The entire card should be a clickable link that navigates to the project's detail page (`/projects/:id`).
    - [x] Use the `ProjectSummaryCard.jsx` component in `Dashboard.jsx` to render the list of projects.
- [x] **Testing**
    - [x] Write API integration tests for the `GET /api/staff/dashboard` endpoint.
    - [x] Write component tests for the `ProjectSummaryCard.jsx` component.
    - [x] Write a component test for the `Dashboard.jsx` page to ensure it fetches and displays the project list.

## Dev Notes

- **Data Models**:
    - **User**: The logged-in user's ID will be extracted from the JWT token by the `auth` middleware (`req.user.id`). [Source: `docs/architecture/4-data-models.md`]
    - **InvestmentProject**: The backend will query the `investmentprojects` collection, filtering by the `assignedTo` field. [Source: `docs/architecture/4-data-models.md`]
    - **Investor**: The `investor` field in the `InvestmentProject` model should be populated to access the `name` for display. [Source: `docs/architecture/4-data-models.md`]

- **API Specifications**:
    - A new route `GET /api/staff/dashboard` will be created.
    - This route will be protected and require a valid JWT token.
    - The response should be an array of `InvestmentProject` objects.

- **File Locations**:
    - **Backend Route**: A new file `oysipa-backend/src/api/staff.js` should be created for staff-specific endpoints.
    - **Backend Controller**: The logic should be added to a new `staffController.js` in `oysipa-backend/src/controllers`.
    - **Frontend Page**: `oysipa-frontend/src/pages/Dashboard.jsx`.
    - **Frontend Component**: A new file `oysipa-frontend/src/components/ProjectSummaryCard.jsx` should be created.

- **Testing**:
    - Backend tests will use Jest and Supertest. [Source: `docs/architecture/coding-standards.md`]
    - Frontend tests will use Vitest and React Testing Library. [Source: `docs/architecture/coding-standards.md`]
